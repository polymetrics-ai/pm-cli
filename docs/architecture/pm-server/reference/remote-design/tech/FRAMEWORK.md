# Framework and client-contract remote design

Research date: 11 September2026. All application checks below are **UNEXECUTED**. Source capture, not a framework benchmark or PM implementation. Source paths are retained in `SOURCE-CAPTURES.json`; release metadata in `UPSTREAM-PINS.json`.

## Actual earlier rationale

**Observed/Verified — document observation.** previous build plan technology T01 chose Go `net/http`/ServeMux and generated std-http strict handlers. Its alternative field says Gin/Fiber were not researched deeply because no distinct capability had been required. It did not find Gin unsuitable, insecure or unscalable. foundation audit repeated that limited comparison. The source is `data/server-build-history/TECHNOLOGY-DECISIONS.json`, T01, also preserved in474. Thus the earlier decision was dependency/contract simplicity under its assumed scope, not an evidence-based rejection of Gin.

**Inferred.** The old rationale does not settle a multi-user remote backend. The API needs cohesive authenticated route groups, administrative separation, generated binding, request lifecycle and consistent error handling. All four candidates can do that; no source supports claiming a router selection determines ETL throughput. Database, workflow, provider and byte-processing paths must be measured separately.

## Verdict

**Proposed/Recommended. Select Gin v1.12.0** with `gin.New()`, explicit middleware and a standard `http.Server`. Choose it for one documented HTTP adapter convention, route groups and mature generated-server integration. Do not use Gin as a validation, identity, workflow or retry engine. The strongest alternative is Chi v5.3.2: it has a smaller dependency/context surface and is equally viable for this contract. Gin's convenience costs an adapter boundary and careful defaults. This is a maintainability decision, not a measured performance win. Revisit before API acceptance if the generated strict adapter cannot preserve cancellation/errors/precision or creates more custom code than the equivalent Chi harness. Do not run two frameworks in production.

**Observed/Verified — inspected implementation.** Gin1.12 `New` trusts all proxy addresses by default and `Default` installs Logger/Recovery ([gin.go202–240](https://github.com/gin-gonic/gin/blob/73726dc606796a025971fe451f0aa6f1b9b847f6/gin.go#L202)); `SetTrustedProxies(nil)` disables forwarded-address trust ([443–454](https://github.com/gin-gonic/gin/blob/73726dc606796a025971fe451f0aa6f1b9b847f6/gin.go#L443)). Its JSON binding defaults disable both UseNumber and unknown-field rejection ([binding/json.go16–55](https://github.com/gin-gonic/gin/blob/73726dc606796a025971fe451f0aa6f1b9b847f6/binding/json.go#L16)). Request-context Deadline/Done forwarding requires ContextWithFallback ([context.go1433–1461](https://github.com/gin-gonic/gin/blob/73726dc606796a025971fe451f0aa6f1b9b847f6/context.go#L1433)). Recovery may print a request dump and raw panic; the dump masks Authorization only ([recovery.go52–105](https://github.com/gin-gonic/gin/blob/73726dc606796a025971fe451f0aa6f1b9b847f6/recovery.go#L52)). These are configuration/integration obligations, not evidence of a PM bug.

**Proposed/Recommended integration:** construct routes once before serving; trusted proxies exact operator-owned ingress CIDRs, nil for direct connections; never trust user-supplied forwarded identity. `gin.New()` plus PM allowlisted slog/recovery, no request dump/raw panic; RFC9457 safe error mapping. Set ContextWithFallback once, but unwrap to `ctx.Request.Context()` in the API adapter before domain calls; never retain pooled contexts or pass them to Temporal. Bound body before reading, reject duplicates/trailing JSON/unknown envelope keys and validate schema/media independently before generated binding. Configure UseNumber once at startup, never mutate binder globals per request. Public dynamic parameters remain schema-bound RawMessage/canonical typed values, not generic float64 maps. Source provider definitions and PM public API schema remain distinct.

**Observed/Verified — inspected generator.** oapi-codegen2.8.0 commit `de2d8b2b0afb287198554eb305bb0d2687d26a85` supports Gin, Echo5 and strict generation. The strict Gin template calls ShouldBindJSON, passes the Gin context to the strict implementation and defaults error output to raw `err.Error()` ([template1–49,77–94,145–161](https://github.com/oapi-codegen/oapi-codegen/blob/de2d8b2b0afb287198554eb305bb0d2687d26a85/pkg/codegen/templates/strict/strict-gin.tmpl#L1)). The README explicitly distinguishes generated checks from full schema validation ([README1347ff](https://github.com/oapi-codegen/oapi-codegen/blob/de2d8b2b0afb287198554eb305bb0d2687d26a85/README.md#L1347)). Therefore PM must configure every generated request/handler/response error callback and test the context adapter; the word strict is not a security guarantee.

**Proposed/Recommended event integration:** a named streaming handler uses standard request cancellation, durable PostgreSQL event queries, bounded buffers, explicit SSE `id`, heartbeat and flush; no generic short request timeout over the stream. Per-write deadline and slow-consumer termination preserve server resources. Gin's convenience `Stream` checks CloseNotify but its callback can block ([context.go1312–1336](https://github.com/gin-gonic/gin/blob/73726dc606796a025971fe451f0aa6f1b9b847f6/context.go#L1312)); PM uses context-aware select and does not infer replay from this helper. Reverse proxy buffering disabled for events, max body limits and streaming-specific idle budgets configured. Native browser EventSource uses same-origin HttpOnly session cookies; CLI uses bearer auth over HTTP SSE. A interrupted watch never cancels durable work.

## Browser SDK and API parity

**Observed/Verified — package/source observation.** openapi-typescript7.13.0 and openapi-fetch0.17.0 are MIT; package manifests inspected at `0cc7ee77d28359c7901d9cd3b5733b70a050ea49`. Typescript package explicitly targets OpenAPI3.0/3.1; fetch is framework-neutral. [typescript manifest1–11](https://github.com/openapi-ts/openapi-typescript/blob/0cc7ee77d28359c7901d9cd3b5733b70a050ea49/packages/openapi-typescript/package.json#L1), [fetch manifest1–24](https://github.com/openapi-ts/openapi-typescript/blob/0cc7ee77d28359c7901d9cd3b5733b70a050ea49/packages/openapi-fetch/package.json#L1). npm metadata captured separately; source manifest versions match. No generated client was executed here.

**Proposed/Recommended.** Generate `sdk/browser/schema.d.ts` with7.13.0 from the identical public PM API document that generates Go SDK types. Wrap openapi-fetch0.17.0 in `sdk/browser/client.ts` with credentials same-origin, CSRF headers and AbortSignal; do not store provider secrets or PM browser refresh tokens in localStorage. JSON exact numbers travel tagged/decimal-string as the common PM value contract, not JS number coercion. Generate-only types are not runtime validation: server validators remain authoritative. Browser API parity test harness has no ETL engine and uses identical scenario inputs/permissions/idempotency as CLI. UI credential entry is a separately scoped server-owned admin page with no secret readback; do not generate its inputs into ordinary CLI or public browser client.

**Proposed/Recommended validation gate, UNEXECUTED:** same test scenario uses Gin API + actual PostgreSQL/Temporal stack and Go CLI/browser SDK. (1) authenticated job submission durable202; duplicate scope/key same run; changed body409; (2) concurrent two-workspace calls fail cross-scope for list/get/update/events/artifacts; (3) malformed/duplicate/trailing/null/precision/media causes zero provider I/O; (4) cancellation before admission vs client disappearance after admission; (5) SSE disconnect/reconnect and terminal snapshot; (6) proxy spoof/header/panic/credential canaries; (7) safe RFC9457 for validation/auth/DB/Temporal errors. Measure end-to-end admission/status latency and allocations under a specified load; no router-only speed claim. Keep Gin imports restricted to `internal/api/http` and composition. Domain/workflow APIs accept canonical value objects and context only.

## Concrete browser acceptance harness

**Observed/Verified — pinned source.** Playwright1.63.0, released2026-09-04 at1b025d7e20a026371cd5f98ba0cdce48892737c8, declares Node>=20 and Apache2. Source/manifest captured in BROWSER-TEST-PIN.json and SOURCE-CAPTURES.json. Its configuration supports per-context baseURL/storage state and per-test overrides; examples are not PM security defaults. [Package manifest](https://github.com/microsoft/playwright/blob/1b025d7e20a026371cd5f98ba0cdce48892737c8/packages/playwright/package.json), [test-use-options31–32](https://github.com/microsoft/playwright/blob/1b025d7e20a026371cd5f98ba0cdce48892737c8/docs/src/test-use-options-js.md#L31). No browsers were installed or tests run.

**Proposed/Recommended.** Use @playwright/test1.63.0 under the isolated test-tool package (Node24 LTS release line, exact distribution/browser lock before M5). It owns a minimal same-origin HTML+generated SDK harness, not a full PM UI. Tests create distinct browser contexts for two users/workspaces and exercise cookie/CSRF/origin denial, approved login, catalog/schema display, run submission/status/reconnect, artifact access, expiry and explicit revocation. Pair them with the Go CLI scenario against the same actual stack. Keep synthetic PM sessions in ephemeral test directories; never persist provider credentials or upload browser traces containing secrets. Do not use ignoreHTTPSErrors in TLS/trust acceptance. Native Node test+fetch is the lighter alternative for SDK shapes but cannot alone prove browser cookie/CORS behavior. Restrict browser automation to these causal integration gates; no duplicate browser suite per provider endpoint. Shipping/browser binary license notices and hashes belong to test-tool distribution, not PM runtime dependencies.
